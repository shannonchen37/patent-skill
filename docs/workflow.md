# Workflow

The canonical workflow is defined in `SKILL.md`. Key invariants:

1. A user must identify a target project separate from the Skill package; without one, guide upload or workspace selection.
2. Ask for an optional proposed patent title. If none exists, mine and propose one after selecting a searched feature combination.
3. The Skill's own files are tooling and never the patent subject.
4. Build the code-evidence map and candidate feature combinations before claims.
5. Perform documented title, semantic, feature-combination, and IPC/CPC searching before selecting the main invention.
6. A renamed title never cures technical overlap; compare claims and technical solutions.
7. Multiple references are not mosaiced to reject novelty.
8. Claims V1 drive the specification; Claims V2 receive final search, eligibility, support, and unity review.
9. Applicant and inventor data are deferred placeholders, not content-generation gates.
10. The software never promises zero collision or emits `FILING_READY`.
