# Workflow

The canonical workflow is the diagram in README. Key invariants:

1. A preliminary claim skeleton precedes documented search.
2. Multiple references are not mosaiced to reject novelty.
3. Claims V1 receive claim-level novelty, inventive-step, and unity review.
4. Claims V2 receive final search, eligibility, and unity review.
5. Human/evidence gaps stop progress; `full` does not guarantee review-ready status.
6. The software never emits `FILING_READY`.
