# Workflow

The canonical workflow is defined in `SKILL.md`. Key invariants:

1. A user must identify a target project separate from the Skill package; without one, analysis stops.
2. The Skill's own files are tooling and never the patent subject.
3. A preliminary claim skeleton precedes documented search.
4. Multiple references are not mosaiced to reject novelty.
5. Claims V1 receive claim-level novelty, inventive-step, and unity review.
6. Claims V2 receive final search, eligibility, and unity review.
7. Human/evidence gaps stop progress; `full` does not guarantee review-ready status.
8. The software never emits `FILING_READY`.
