# CN drafting workflow

First require a user-identified target project that is separate from the Skill package. Never analyze the Skill's own files as the patent subject. Follow the artifact order in `SKILL.md`. Treat drafting as iterative: analyze a preliminary claim skeleton, draft Claims V1, recheck actual claims, draft the specification, produce Claims V2, then recheck search, eligibility, and unity again. Stop on missing targets or unresolved facts instead of filling gaps.

`READY_FOR_ATTORNEY_REVIEW` means the review package is organized; it does not mean rights, patentability, or filing compliance have been decided.
