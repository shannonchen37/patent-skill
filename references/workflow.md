# CN drafting workflow

First require a user-identified target project separate from the Skill package, then ask whether the user has a proposed patent title. Treat the title only as an intent and search seed. Never analyze the Skill's own files as the patent subject.

Follow the content-first artifact order in `SKILL.md`: engineering-evidence map plus confirmed technical disclosures, feature combinations, prior-art search, selected concept, Claims V1, specification, Claims V2, canonical support, hash-bound final search, clean application draft with conditional figures, and hash-bound audits. Applicant and inventor form data may remain `【待填写】` and must not block content generation.

Treat drafting as iterative. Search before selecting the main invention and again after Claims V2. A title change alone never resolves technical overlap. For a missing material mechanism, provide one parameter-light candidate completion and ask one focused question. Rejection returns to the remaining project evidence; confirmation creates TD provenance only after an enablement check. Never fabricate a distinction, effect, metric, or prior-art conclusion.

`CONTENT_READY_FOR_ATTORNEY_REVIEW` means the technical content is organized. Independent audit and DOCX rendering follow as distinct states; none decides rights, patentability, or filing compliance.
