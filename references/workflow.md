# CN drafting workflow

First require a user-identified target project separate from the Skill package, then ask whether the user has a proposed patent title. Treat the title only as an intent and search seed. Never analyze the Skill's own files as the patent subject.

Follow the content-first artifact order in `SKILL.md`: code-evidence map, complete feature combinations, documented prior-art search, closest-reference comparison, selected inventive concept, Claims V1, specification and drawings, Claims V2, final search and support review, then the content package. Applicant and inventor form data may remain `【待填写】` and must not block content generation.

Treat drafting as iterative. Search before selecting the main invention and again after Claims V2. A title change alone never resolves technical overlap. Stop only when the target is missing or a material technical fact cannot be safely marked `【待补充】`; never fabricate a distinction, effect, metric, or prior-art conclusion.

`READY_FOR_ATTORNEY_REVIEW` means the review package is organized; it does not mean rights, patentability, or filing compliance have been decided.
